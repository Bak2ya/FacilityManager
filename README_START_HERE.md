# FacilityManager v0.16.0 · Build21

기본 환경은 GitHub Pages(HTTPS)입니다. 별도 서버 설치가 필요하지 않습니다. 이번 결과는 배포 준비본이며 GitHub에 직접 게시하지 않았습니다.

## 기존 사이트 업데이트

GITHUB_PAGES.zip을 풀어 앱 실행 파일을 갱신하세요. **기관에서 사용하던 site-config.json / latest-db.json은 업로드 대상에서 제외하고 기존 값을 유지하세요.** ZIP에는 개발 작업공간의 설정이 들어 있으므로 기관의 운영 설정을 대신하지 않습니다. 처음 게시할 때만 확인 후 사용하세요. 이번 개발에서는 기존 두 설정파일 내용을 바꾸지 않았습니다.

## 처음 사용하는 경우

1. 시작 화면 → **새 FACI 만들기**.
2. 기관명 → 일반 관리자 암호/확인 → 최상위 관리자 담당자명·암호/확인. 두 암호는 달라야 합니다.
3. 최상위 관리자 **복구키 별도 저장** → **FACI 파일 저장**. 다운로드 목록에서 두 파일을 확인하고 서로 다른 곳에 보관하세요.
4. 빈 FACI에서 수정 모드의 **PPKG 도면 추가**. 도면이 없어도 FACI를 만들고 보관할 수 있습니다.
5. 공간 선택 → 편집에서 업무정보를 입력하고 **FACI 파일 저장**. 편집창 입력은 먼저 ‘적용’해야 합니다.

## 다음 사용부터

- **FACI 파일 열기**: 선택한 파일을 읽기 모드로 엽니다.
- **브라우저 작업본 이어보기**: 이 브라우저에 보관한 문서입니다. 파일의 최신 여부를 뜻하지 않습니다.
- **최근 연 FACI 보관본 열기**: 마지막 파일 선택 당시 내용입니다. 디스크 파일을 자동으로 다시 읽는 기능은 아닙니다.
- 상단 **읽기 / 수정** 전환. 수정 시 관리자 암호로 인증하며 현재 도면·선택·확대 위치를 유지합니다.
- 일반 관리자는 시설정보를 수정하고 최상위 관리자는 계정·권한도 관리합니다. 복구키는 기존 복구 소유자만 발급합니다.
- **이 기기에 작업본 보관**과 **FACI 파일 저장**은 별개입니다. 파일 저장 요청 후 다운로드 완료 여부를 확인하세요. 원본 파일을 자동 덮어쓰지 않습니다.
- **도면만 PPKG로 내보내기**는 원본 패키지별로 ID·범위·리비전을 보존하고 업무·계정·보호정보를 제외합니다.
- 오프라인은 설정 → **오프라인 사용 준비**. Build21로 업데이트한 기기는 다시 준비하세요. 브라우저 종료 경고는 모바일에서 항상 나타나지는 않습니다.
